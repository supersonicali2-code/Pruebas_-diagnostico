⚡ 1. CAPA ELÉCTRICA Y CALIDAD DE ENERGÍA

Prueba 1.1: Mediciones de Voltaje con Multímetro en Tomacorriente

💡 Software / Herramienta: Multímetro Digital True RMS.

⚙️ Procedimiento detallado: Con el multímetro configurado en Voltios AC (V~), mida directamente en el tomacorriente que alimenta el servidor:

  • Fase a Neutro (F-N): Verificar que el voltaje sea el nominal de red (ej. 120V o 220V AC).
  • Fase a Tierra (F-T): El valor debe ser equivalente al voltaje de Fase a Neutro.
  • Neutro a Tierra (N-T): Medir diferencial. Debe ser menor a 1V AC para evitar corrientes parásitas en la fuente de poder y componentes del servidor.

FUENTE / BIOS-UEFI

Prueba 1.2: Mediciones de Fuentes de Poder desde BIOS/UEFI

💡 Herramienta: Monitor de Hardware de la BIOS/UEFI de la placa base o servidor.

⚠️ Nota técnica: Los valores de Vcore y SoC dependen del procesador, placa base, carga y configuración. Los rangos indicados son referencias iniciales; prevalece la especificación del fabricante.

⚙️ Acceso BIOS/UEFI: Apague o reinicie el servidor. Durante el POST presione repetidamente F2 o Delete (Supr). En equipos Dell suele utilizarse F2; HP suele utilizar F9; Lenovo suele utilizar F1/F2. También puede acceder desde Windows mediante Configuración → Sistema → Recuperación → Inicio avanzado → Reiniciar ahora → Solucionar problemas → Opciones avanzadas → Configuración de firmware UEFI, cuando el equipo lo permita.

📍 Ruta habitual: BIOS/UEFI → Hardware Monitor / PC Health Status / Monitoring / H/W Monitor. Los nombres cambian según fabricante.

🌐 2. CAPA DE RED Y COMUNICACIONES
RED

Prueba 1.3: Latencia y Pérdida de Paquetes

💡 Software / Herramienta: Símbolo del Sistema (CMD) de Windows.

⚙️ Sintaxis general: ping [IP_o_Host_Destino] -n [Cantidad_Paquetes]

⚙️ Ejemplo práctico: Abrir CMD y ejecutar el siguiente comando para evaluar 100 paquetes continuos:

ping 192.168.10.100 -n 100

Criterio de éxito: 0% de paquetes perdidos y latencia estable (< 5ms en red local).

Sin foto
RED

Prueba 1.4: Conexión de Sockets TCP (Puerto por Puerto)

💡 Software / Herramienta: PowerShell de Windows.

⚙️ Sintaxis general: Test-NetConnection -ComputerName [IP_o_Host] -Port [Puerto]

⚙️ Ejemplo práctico: Abrir PowerShell y ejecutar el cmdlet para probar sockets TCP en puertos específicos de GeoVision (ej. 4550):

Test-NetConnection -ComputerName 192.168.10.100 -Port 4550

Prueba 1.6: Verificación de MTU y Fragmentación (Path MTU)

💡 Software / Herramienta: Símbolo del Sistema (CMD).

🌐 Metodología de Campo: Esta prueba se realiza de forma bidireccional entre la Estación de Monitoreo y el Servidor, tambien realice la prueba en la ruta Servidor ➔ Cámara IP.

⚙️ Sintaxis general: ping [IP_Destino] -f -l [Bytes_Buffer]

⚙️ Ejemplo práctico:

ping 192.168.10.100 -f -l 1472

Prueba 2.1: Diagnóstico de Discos Duros (S.M.A.R.T. y Rendimiento I/O)

💡 Software / Herramientas: CrystalDiskInfo, Victoria, HDDscan o herramienta propia del fabricante (para S.M.A.R.T.) y CrystalDiskMark (para velocidad I/O).

⚙️ Uso y aplicación: Abrir el software seleccionado para verificar el estado de salud general de cada unidad física. Luego, abrir CrystalDiskMark y seleccionar la unidad para realizar pruebas de escritura secuencial (SeqQ32T1) con bloques de 1GiB.
